## 一、阶段 0：雏形——先有 API 再有产品（2025-11-03 ~ 11-07）

起步只有一个 Express 后端，按「账号 → 内容 → 互动」的依赖顺序铺 API：

1. `5a516c0` Initial commit，Express + MySQL 连接池跑通；
2. `19ab3e8` addToken——用户表 + JWT 签发，先解决"谁在请求"；
3. `1a4435b` reset db users、`7833a95` comment、`d3aa93d` 二级评论修复——评论模型（含两级结构）在第一周就定型，这个早期决定一直沿用到最后；
4. `7478706`/`b097efa` 数据库文档 + 文章接口基本完成——**数据库文档与代码同步诞生的习惯从第二天就开始了**；
5. `a3c87d2` 消息接口完成。

这一周的产出是 5 张核心表和对应 CRUD。随后项目搁置了近 11 个月——重启后证明这段骨架是可用的，说明**先把数据模型和认证链路想清楚再停工，代码是能等人的**。

## 二、阶段 1：重启与联通——先修安全，再谈功能（2026-10-15 ~ 10-21）

重启后第一件事不是加功能，而是把前后端接起来并补上质量底线：

1. `ea89b0e` 新增前后端互联——Vue 3 + Vite 前端接入既有 API，跑通登录到列表的最小链路；
2. `2c9569a`/`c92c475` 两个关键安全修复：普通用户不能绕过审核改文章状态、普通用户写操作收敛为仅草稿；
3. `a6e1365` 评论校验：必须评论已发布文章、回复必须同属一篇文章；
4. `8f2da6e`/`3264af7`/`a674f1c`/`0e73e7f` **每个修复配一组测试**，并修正 mock 路径——测试文化从这天建立；
5. `8e0533c` 合并 PR #1「修复文章审核与评论安全问题」，走了一次完整 PR 流程。

**本阶段方法论成型**：发现问题 → 修复 → 测试钉住 → 合并，这个四拍节奏贯穿了之后所有提交。

## 八、方法论提炼：这个项目是怎么"一步步"做对的

### 8.1 顺序选择的逻辑

回头看，搭建顺序有一条清晰的主线：**先立数据模型 → 再通认证链路 → 后端模块逐个接入数据库 → 后台管理成形 → 面向访客的门户 → 安全与权限体系化 → 组件统一与体验收尾**。每个阶段都建立在前一阶段的稳定结论上：门户的公开接口（`625262b`）是在后台接口分离之后才开的口子；权限矩阵是在内容模块全部就位后才覆盖判定；组件统一是在前后台各自长出重复实现之后才合并的。**不要过早抽象，也不要过早开放公开面**。

### 8.2 可复刻的工作节奏

1. **功能分支 + 快进合并**：早期走 PR（#1、#5），后期统一为 `codex/*` 功能分支，合并前先拉取远程确认 `main` 无新提交；单日多个小分支并行，每个分支只做一件事。
2. **修复必须配测试**：`2c9569a`（修复）与 `8f2da6e`（测试）成对出现是全仓库惯例；测试数从 10-26 的 117 项一路长到 10-29 的 337 项（前端 63 项），只增不减。
3. **文档同步提交**：几乎每个功能分支都带一条"更新开发进度与 README"提交——文档不是阶段末补写的，是随代码走的。
4. **验证方式逐级演进**：单元测试（mock 数据库）→ 真实 MySQL 集成测试（独立验证库，用后即删，禁指业务库）→ 3031 临时端口 HTTP 冒烟 → 无头 Chrome 端到端 → 浏览器人工复测。写操作验证后一律还原数据。
5. **数据库变更走迁移脚本**：2026-10-23 起所有 DDL 以 `YYYYMMDD_名称` 迁移文件登记，`npm run db:migrate` 幂等执行，`schema_migrations` 记账——后期举报、私信的多次加列都靠这套机制零事故。
6. **视觉问题小步快跑**：红点定位改 5 版、设置页布局修 6 轮，都在隔离分支里反复调，主干只接收定稿。

### 8.3 踩过的坑（均为开发期真实发生、已修复）

| 坑 | 表现 | 根治方式 |
| --- | --- | --- |
| 权限绕过 | 普通用户可改文章状态绕过审核 | 控制器收敛 + 测试钉住（2026-10-21） |
| record 表只写不删 | 访问记录无限增长 | 保留期滚动清理，分批 DELETE（2026-10-26） |
| 上传 Token 暴露 | 长期 JWT 随 URL 进访问日志 | 短期一次性票据（2026-10-26） |
| 软删不彻底 | "已删"文件仍留在公开目录 | 移入非公开备份区 + 生命周期任务（2026-10-27） |
| 注册并发冲突 | 唯一键冲突返回 500 | 按约束名稳定映射 400（2026-10-27） |
| 访问统计越权 | 游客可见全站统计 | 总览口径按权限收窄（2026-10-29） |
| 临时文件污染仓库 | 调试产物误提交 | `.gitignore` 规则 + 删除遗留（多次） |

## 九、如果照着重做一遍：十步清单

1. 定数据模型并写数据库文档（账号、内容、互动三域先想清楚两级评论这类结构性决定）；
2. 搭 Express + 连接池 + JWT 骨架，先跑通注册/登录/用户信息；
3. 前端最小壳接通登录到列表的最小链路；
4. 给认证与内容权限写第一批测试，确立"修复配测试"节奏；
5. 后端基础设施加固（CORS、限流、错误处理）后再批量接入业务模块，一天一个域，模块间共用表结构先确认（如图库复用文章表）；
6. 建立 `YYYYMMDD` 迁移机制，此后所有 DDL 不再手改库；
7. 后台横向铺齐：统计、日志、设置、文件——先做对再抽通用组件；
8. 门户单独立项：先拆页面结构，再做视觉，最后做性能（分包、按需注册、缩略图）；
9. 安全体系化：权限矩阵、密码重置令牌、安全头与限流一次性打包上；公开接口与后台接口始终分离；
10. 收尾先统一重复组件，再补互动闭环（举报、私信、SEO），每步带测试与文档提交。
