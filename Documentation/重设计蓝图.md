## 一、设计立场：五条第一天默认值

| # | 默认值 | 对应现状问题 |
| --- | --- | --- |
| 1 | 图片在盘上，不在库里 | `image` 表 MEDIUMBLOB，库体积随上传线性增长（挂账技术债） |
| 2 | 凭证在 Cookie 里 | 上传整套短期票据机制只为绕过「yk-upload 发不了 Authorization 头」 |
| 3 | 内容是结构化的 | wangEditor 存 HTML 字符串，展示端永远靠 DOMPurify 洗数据，editor chunk 812KB |
| 4 | 类型只有一份 | `lin_blog/src/api/*.ts` 的 interface 手工镜像后端 JS 返回，漂移只能运行时发现 |
| 5 | CI 守着预算 | 测试只在本地跑，812KB 超标靠人记得 |

**总原则**：领域模型、权限思想、安全直觉原样保留；换的是存储位置、认证载体、富文本方案、类型断层、工程化底线这五样基础设施。

## 二、保留清单（明确不动的设计）

这些决定被 263 个提交的历史验证过，重做也照抄：

1. **图库复用内容表**——`article.classify='article'|'image'` 省掉整套重复 CRUD 与互动代码，蓝图下正式化为 `content` 表 + `content_type` 字段，语义不变；
2. **权限矩阵**——`role_permission` 表、37 项权限分 7 组、受保护权限（`permission.edit`/`user.assignAdmin`）、超管唯一性用数据库唯一生成列约束（`uk_single_super_admin`）、进程内缓存 + 保存即刷新；
3. **`token_version` 机制**——改密/重置后旧凭证立即失效；
4. **安全直觉**——无权限统一 404 防探测、重置令牌只存 SHA-256 且 30 分钟单次、浏览量按「登录 ID / IP+UA 哈希」30 分钟去重、计数冗余列 + 明细表回退（`GREATEST` 防负数）；
5. **配置启动强校验**——`serve/config/default.js` 不合规即拒启的思路保留，蓝图下用 zod 统一表达；
6. **文档随代码走 + 「修复必配测试」节奏**——这是流程资产，与代码无关；
7. **搭建顺序**——模型 → 认证 → 模块入库 → 后台 → 门户 → 权限体系化 → 统一收尾的主线照走；
8. **复杂度克制**——单进程 + 单库 + 反向代理，不微服务、不上消息队列、不做多租户。

## 三、逐项设计

### 3.1 仓库与语言：Monorepo + 全栈 TypeScript

- **现状与代价**：后端纯 JS；前端 `lin_blog/src/api/` 13 个文件里的 interface 是手工镜像（仅 `article.ts` 就 233 行，大半是类型）。后端改一个字段，前端要人肉同步，漏了就是运行时错误。
- **设计**：pnpm workspaces，`apps/web` + `apps/server` + `packages/shared`。shared 包用 **zod schema 定义每个接口的入参/出参**，TypeScript 类型由 schema 推导：服务端运行时校验请求、启动时校验环境配置，前端直接 import 同一份类型。现在 `.env` 校验、`normalizeJsonBody`、各控制器里手写的参数校验统一收进 schema 一处表达。
- **代价**：后端整体迁 TS 是本蓝图最大的一次性工程量；可先用「shared 包只放 schema + JS 侧 JSDoc 引用」过渡。

### 3.2 数据层：图片出库、标签关联表、查询构建器

- **图片出库**：磁盘目录 + 可插拔 storage driver（`local` / `s3` 同一接口），DB 只存元数据 + SHA-256 去重；sharp 缩略图生成后**落盘缓存**，不再每次请求在 64MB 内存 LRU 里现算。现有 `serve/utils/fileStorage.js`、`fileOffsite.js`（跨盘镜像 + S3 异地副本）已经是这套接口的雏形，图片模块直接复用同一抽象。
- **标签关联表**：逗号分隔 + `FIND_IN_SET`（见 `serve/model/dbModel/article/index.js` 的标签筛选分支）永远走不了索引。改 `content_label` 关联表，代价是一个 join，收益是筛选、统计、重命名都能走索引。
- **查询构建器**：手写 SQL 字符串拼接换 Drizzle + drizzle-kit 迁移。分层不变（查询仍收在模型层），动态 WHERE 不再拼字符串，迁移机制不用自研 `schema_migrations` 记账。
- **保留**：计数冗余列（`likes`/`comments` 在内容行上）+ 明细表（`comment_praise` 等）事务内回退的写法；`view_log` 哈希去重与保留期清理。

### 3.3 认证：Cookie Session 替代 localStorage JWT

- **现状与代价**：JWT 存 localStorage，7 天有效；`serve/middleware/auth.js` 里 `authMiddlewareFromQuery` + `serve/utils/uploadTicket.js`（票据 5 分钟、默认 50 次、池上限 5000、只存 SHA-256）整套机制存在的唯一根因是 **yk-upload 用 XHR 发不了自定义请求头**。
- **设计**：httpOnly + SameSite 的 Cookie session。浏览器对所有请求（含上传组件）自动带凭证，**票据机制整个消失**。形态：access token 15 分钟 + refresh token 轮换（带复用检测，refresh 只能用一次，重放即吊销会话）；`token_version` 机制原样保留。
- **注意**：CORS 从「允许 Authorization 头」变为「精确来源 + credentials」，跨域部署时前后端最好同站（子域 + Cookie domain），这点在部署设计里一并解决。

### 3.4 富文本：Tiptap（ProseMirror JSON）替代 wangEditor

- **现状与代价**：editor chunk 812KB 超 600KB 阈值；HTML 字符串入库导致正文是不可信数据，展示端必须 DOMPurify 兜底，检索/版本 diff/导出都只能对着字符串做。
- **设计**：Tiptap 按需 tree-shake（只装用到的扩展），存 ProseMirror JSON：**内容是结构不是字符串**——渲染是确定性遍历，无需消毒；全文检索对 JSON 提取纯文本建列；将来做版本历史、字数统计、导出 Markdown 都有结构可查。
- **迁移代价**：存量 HTML 需一次性转换脚本（HTML → Tiptap JSON，失败条目保留原样双轨渲染）；这是蓝图里唯一需要数据迁移的破坏性项。

### 3.5 实时：SSE 替代轮询

- **现状与代价**：`lin_blog/src/utils/messageRealtime.ts` 20 秒轮询、页面隐藏即停，延迟最坏 20 秒且空转请求不少。
- **设计**：一条 SSE 事件流（`/api/events`，认证后订阅）推消息未读、举报待处理角标、系统通知；反代下不需要 WebSocket 升级，浏览器原生重连。举报工作台的「跨组件事件即时刷新」也可并入。

### 3.6 工程化：CI 与体积预算

- GitHub Actions：lint + 后端 `npm test` + 前端 `vue-tsc`/`npm test` + 构建 + **size-limit**（首屏与 editor 类重 chunk 分别设预算），超预算即红——812KB 这类问题在合入前被拦住而不是上线后被想起；
- docker-compose 起 MySQL 供本地与 CI 一键拉起；pino 结构化日志 + request id（现在 `requestContext` 已有雏形，收编为正式设施）。

### 3.7 部署：docker compose 三件套

`app` + `mysql` + `Caddy`（自动 HTTPS 反代，`trust proxy` 天然成立）；数据卷挂 MySQL 与文件目录，`mysqldump` 定时 + 备份目录异地副本。个人博客一台 2C4G 足够，扩容路径是「先拆库、再拆对象存储」，不需要预设更多。

## 四、明确不做的

微服务、消息队列、多租户/SaaS 化、第三方登录、国际化、客户端 App。复杂度上限就是「单进程 + 单库 + 反向代理」——现有项目对这条线的克制是正确的，蓝图继承。

## 五、蓝图与现状的映射

| 蓝图项 | 现状机制 | 演进方式 | 一次性代价 |
| --- | --- | --- | --- |
| Monorepo + shared 类型 | 前后端分仓目录、手抄 interface | 大重构，适合重写期做 | 大 |
| 图片出库 | `image` 表 MEDIUMBLOB + 内存 LRU 缩略图 | **可原地演进**：新增落盘存储，迁移脚本搬历史图片（`20261024_image_storage` 迁移有先例） | 中 |
| 标签关联表 | 逗号分隔 + `FIND_IN_SET` | 可原地演进：加表 + 双写 + 迁移 + 切查询 | 中 |
| Cookie session | localStorage JWT + 上传票据 | 可原地演进但横切面大（前端请求层、上传、CORS 全动） | 大 |
| Tiptap | wangEditor HTML 字符串 | 可原地演进：转换脚本 + 双轨渲染过渡 | 中 |
| SSE | 20 秒轮询 | 可原地演进：后端加事件端点，前端换订阅 | 小 |
| CI + size-limit | 纯本地测试 | **可原地演进，无破坏**，建议最先做 | 小 |
| docker compose 部署 | 裸进程 + 反代约定 | 随 M2 部署一并引入 | 小 |

## 六、结论

两条路径都成立：**全量重写**（按蓝图第一天即五条默认值齐备，适合当作下一个个人项目的起点）或**原地演进**（按上表代价从小到大做：CI → SSE → 图片出库 → 标签关联表 → Tiptap → Cookie → Monorepo，前三项互不依赖可随时插进现有里程碑）。无论哪条，这套重设计的收获是同一个：**好设计常常不是想出来的，是把踩过的坑提前修进地基里**——五条默认值里有四条，正好对应这个项目已经挂账或已经绕行的四个问题。
